# 導讀 · What I Learned Deploying OpenClaw Beyond Demos

> **這篇是七篇裡最貼這次黑克松題目的**——整篇就在講「agent 住在哪裡才會變成真的有人用」。

---

## 核心論點

作者做 OpenClaw 客戶案子三個月：部署、寫自訂 skill 和 CLI 工具、弄壞、修好，
找出「新鮮感退掉之後還撐得住的是什麼」。

> 網路上 agent demo 很多。大部分玩五分鐘很有趣，一週後就沒用了。
> 有趣的問題是：第一次設定的興奮退掉之後，人們還會不會繼續用。

她的結論：留得下來的 workflow 都是**同一個形狀**。

> 1. 它們**住在人們原本就在用的工具裡**。
> 2. 它們**把脈絡帶著走**，不是每次從零開始。
> 3. 它們**省時間，又不需要你一直盯著**。

**這三條可以直接當這次黑克松的自我檢查表。**

---

## 客戶案子裡真的留下來的（題目靈感清單）

| workflow | 做什麼 | 為什麼留得下來 |
|---|---|---|
| 每日簡報 | 拉行事曆脈絡，挑出當天最重要的事，寄摘要 | 一早就降低了規劃的負擔 |
| 個人 CRM | 把人與關係的豐富脈絡存在 Obsidian | 把散落的筆記變成通話前真的用得上的東西 |
| 家庭排程 bot | 在 iMessage 群組裡處理來回的排程 | **沒人需要打開另一個排程工具** |
| 餐廳電話訂位 | Resy／OpenTable 資料不全時直接打電話去訂 | 做了標準 app 常常做不到的事 |
| 開會前 dossier | 開會前整理某人／某公司的關鍵脈絡 | 省掉切換一堆分頁，讓你有備而來 |
| 人脈關係圖 | 畫出創辦人與投資人網絡裡誰認識誰 | 讓「暖介紹」的機會看得見 |

> 共通點很簡單：OpenClaw 停止扮演一個玩具聊天介面、
> 開始表現得像**背景基礎設施**的時候，才變得有價值。

---

## 動手之前的現實提醒

> 這不是一個兩小時的支線任務。

需要：OpenClaw 裝好設定好、Node.js 18+、編輯器、Git。
時間：**想做出真東西而不只是 demo，要一個週末。**
帳號：一個 LLM 供應商、Telegram（通知用）、Obsidian（要做知識系統的話）。

> OpenClaw 很強，但不是開箱即用。預期會有設定工作、反覆調整、偶爾一團亂。

## 系統一 · 研究 agent

問題不是資訊不夠，是**太多**。單看 arXiv 就超過她能掃的量，
而且一邊覺得自己在「跟上」，一邊其實漏掉好東西。

> 我不想要再一個資訊流。我想要一個幫我過濾、只在真的有理由時才打擾我的東西。

於是做了 **Robin**，一個每晚跑的研究 agent。職責**刻意做得很窄**：
搜一小組主題 → 狠狠過濾 → 摘要重要的 → 結果不夠好就保持安靜。

核心指令檔的形狀（摘要）：搜 arXiv 上 AI agents／多 agent 系統／LLM 推理三個主題；
只留下同時**新穎且對 builder 有用**的論文；寫 200 字以內的簡報；
**如果通過的好論文少於 3 篇，就回 `NO_REPLY`**。
過濾規則：跳過綜述和小幅基準提升；偏好有實務意涵的；假設我在意槓桿而非完整性。

排程不用手寫 cron 語法，可以用白話描述讓 OpenClaw 生成：

```bash
openclaw cron add \
  --name "Robin Research" \
  --schedule "0 23 * * *" \
  --task "依照 research-instructions.md 做每晚研究：搜尋、過濾、綜合、品質管控。"
```

> 讓這東西有用的關鍵是**節制**。
> 這個 agent 最好的版本是有主見的、重複的、還有點無聊。
> 它該知道什麼算訊號、什麼該忽略、以及什麼時候不要煩你。

要再抄一次這個 workflow 的話，她會守三條規則：

1. 從**一個結構化、可預期**的來源開始
2. **讓「沉默」是可接受的輸出**
3. 先把過濾調好，再加資料來源

> 這就是「好玩的 demo」和「我真的一直開著的工具」之間的差別。

## 系統二 · 會從決策學習的知識系統

她說這個比較不炫，但**更重要**。

> 大部分工具很會存事實。它們通常漏掉的是人後來真正想要的那部分：
> **一個決策當初為什麼那樣做、哪個取捨重要、上次遇到類似的事發生了什麼。**

四個步驟：

1. **基本事實存 Obsidian** —— 人物頁、專案筆記、關係脈絡、對話之間的連結。
   「這是無聊但必要的一層。如果 agent 連基本事實都搞不清，其餘都不重要。」
2. **決策推理存 Honcho**（一個為 agent 長期記憶設計的工具）——
   存決策、脈絡、推理、先例。
3. **兩層一起查** —— 問題像「我該把 Sarah 介紹給誰」、
   「這次定價談判該怎麼處理」、「上次選供應商學到了什麼」，
   它從 Obsidian 拉事實、從 Honcho 拉決策模式，合起來回答。
4. **拿真實決策測一次** —— 例如「我們選 Stripe 而不是 Square，
   因為 API 文件比較好，而且上個專案用 Stripe 體驗不錯」。
   agent 應該要能存下：決策、脈絡、推理、先例，四個部分分開。

> 這聽起來不華麗，但複利就是從這裡開始。
> 六個月後，價值不在於 agent 記得人名。
> 而是它能說：「這種情況我們見過類似的版本。當時什麼有用、什麼失敗、為什麼。」

她稱之為 **institutional memory（組織記憶）**：不是剪貼簿，是一份可用的決策紀錄。

## 系統三 · SnapshotClaw：給 agent 的大腦做備份

觸發點是凌晨兩點一個壞掉的設定檔。agent 回來時狀態很糟：
skill 不見了、cron 消失了、記憶飄掉了。

> 那種失敗會讓你意識到你的 agent 已經不只是一個 prompt。
> **它的大腦變成了有價值的狀態，而那個狀態需要一個復原計畫。**

最短的描述：**它是你 OpenClaw 環境的版本控制。**

要備份的東西：

```
~/.openclaw/config/    # agent 設定
~/.openclaw/cron/      # 排程自動化
~/.openclaw/skills/    # 安裝的能力
~/.openclaw/memory/    # 對話與狀態資料
~/.openclaw/plugins/   # 擴充
```

```bash
brew tap kayacancode/snapshotclaw && brew install snapshotclaw
cd ~/.openclaw && snapshotclaw init
snapshotclaw create --name "baseline-setup"

snapshotclaw list --limit 5
snapshotclaw diff 2026-03-05-backup current
snapshotclaw restore 2026-03-05-backup
```

**最好的理由不是備份本身**：

> 這改變了我的工作方式，因為它移除了一部分恐懼。
> 知道我可以回到一個已知良好的狀態，我就**更敢亂搞**。

> 如果你認真要長期跑 agent，這件事很重要。
> 難的部分很少是生成文字。難的部分是把整個系統維持得夠穩定，
> 讓你在很糟的一天過後還信得過它。

## 系統四 · 把 OpenClaw 的腦放進機器人

在 AI Tinkerers NYC 場，她 demo 了一台 Hugging Face **Reachy Mini**
（有關節動作、麥克風、鏡頭的桌面機器人）配 OpenClaw 的大腦。

> 讓這個 demo 對我來說有意思的**不是硬體本身**。
> 而是這台機器人不是一個有罐頭回應的獨立玩具。

她把它接上 Botwick（John Borthwick 的 OpenClaw agent），
所以它**繼承了一個既有 agent 系統的記憶、脈絡和人格**。

於是機器人能做的不只是講話：記得先前的對話、認出認識的人、
用動作表達情緒、把語音輸入橋接進她**本來就在用的**那些 OpenClaw workflow。

語音管線：

```
Mic → VAD → STT（Nemotron／Whisper）→ Claude via OpenClaw → ElevenLabs TTS → Speaker
```

（VAD = voice activity detection，偵測「現在有人在說話嗎」。
STT = speech to text，語音轉文字。TTS 反過來。）

**但關鍵在隔天**：

> 讓它感覺真實的不是 demo 本身，是**第二天**。
> 活動結束後，我把系統接上 Spotify 控制器，現在它管辦公室的音樂。
> 我可以叫它停、跳過、或播符合當下氣氛的東西。
> 那是個很小的用途，但它重要，因為它讓機器人從**「展示品」變成「我真的在用的東西」**。

> 這又是同一個模式。**魔力不在具身本身。
> 魔力在於那個實體介面接進了一個已經懂你脈絡的持久數位系統。**

repo：`kayacancode/reachy-brain`

---

## 四個系統教她的同一件事

| 系統 | 它證明了什麼 |
|---|---|
| 研究 agent | agent 在**狠狠過濾、結果不好就保持安靜**時才有用 |
| 知識系統 | 長期價值來自**保存推理**，不只是存事實 |
| SnapshotClaw | agent workflow 一旦成為真實工作的一部分，就需要復原與版本控制 |
| Reachy 整合 | 實體介面在**接上你其餘技術棧同一份記憶與 workflow** 時才變得有趣 |

她對未來的看法：

> 我不認為未來是「每個人跟一個更好的助理聊天」。
> 我認為我們正在看個人 AI 走進**背景**。
> 它跟你一起讀、替你記得、看著你的行事曆、追蹤你的人際關係、
> 撐過設定失敗，最終透過**當下最方便的那個介面**出現：
> 你的終端機、你的手機、你的筆記 app、你的聲音，或桌上的一台機器人。

結尾兩句（這篇最好記的部分）：

> 一旦 agent 有了記憶、脈絡，以及你原本就活在裡面的那些工具的存取權，
> 它就不再像一個一次性的產品。它開始像你環境的一部分。
>
> **你不是登入它。你是跟它一起生活。**

## 對這次黑克松的用處

這篇幾乎就是評審心裡那張評分表。

如果走眼鏡那條路，pitch 的骨幹就是那句
「**實體介面 + 一個已經懂你脈絡的持久系統**」——
不要只 demo「眼鏡會講話」，要 demo「眼鏡接上了我原本的工作流」。

另外那句「**讓沉默是可接受的輸出**」很反直覺但很好用：
一個知道什麼時候不要打擾你的 agent，比一個什麼都回答的 agent 更像真產品。
