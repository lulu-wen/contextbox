# 看過但沒採用的專案

每一條都寫清楚**為什麼不用** —— 這樣以後有人再提，不用重查一次。
數字在 2026-09-13 用 GitHub API 驗證過。

---

## 檔案整理

### AI File Sorter
<https://github.com/hyperfield/ai-file-sorter>　**AGPL-3.0**　1717★　2026-09-11

掃描 → LLM 分類（含圖片）→ **逐列預覽可編輯** → 提交搬移。跨平台桌面應用，維護活躍。

**為什麼不用**：**AGPL-3.0 會傳染整包。** 碰了它的碼，ContextBox 就得跟著 AGPL。

**學到什麼**：它的**逐列批准 UX** 是對的 —— 不是「全部同意」一顆按鈕，
而是每一列都能單獨取消。→ 我們的收件匣卡片照這個做（C 負責）。
**只看畫面，不看碼。**

### Local File Organizer
<https://github.com/QiuYannnn/Local-File-Organizer>　MIT　3338★　**2024-10-21 之後沒動過**

完全本機、每個檔案一個 JSON prompt 丟給本地模型分類。

**為什麼不用**：快兩年沒更新。授權沒問題，但沒有可以直接用的東西。

**學到什麼**：「每個檔案一個 JSON prompt」的形狀 → 我們的 `core/prompt.ts`。

### organize
<https://github.com/tfeldmann/organize>　MIT　3143★　2026-09-07

規則式檔案整理（不是 AI），成熟、活躍。**有 simulate 模式。**

**為什麼不用**：它是規則引擎，不是理解引擎。方向不同。

**學到什麼**：**simulate-before-execute** 的習慣 —— 先讓人看到「會發生什麼」，
再問要不要做。→ 我們的 propose／apply 就是這個。

### AI-File-Organizer-Agent
<https://github.com/TheSethRose/AI-File-Organizer-Agent>　**沒有 LICENSE**　37★　2025-04-04

propose → approve → move，但沒有索引也沒有文件理解。只有 2 個 commit，同一天建立與結束。

**為什麼不用**：**沒宣告授權 = 保留一切權利**，不可以把碼複製進公開 repo。
而且是 demo 等級。

### llama-fswatch

**查不到這個 repo。** 之前的筆記裡有這一條（說是 MIT、watch → 建議檔案樹 → Electron），
但 2026-09-13 用 GitHub API 查是 404，搜尋也找不到。

**當作不存在。** 這一條列在這裡是為了記錄：
**筆記裡的 URL 沒驗證過就不要當成事實。**

### Digital Vault

2021 年的 Go 歸檔 CLI，沒有 AI。AGPL-3.0。已經死了。**無關，排除。**

## 已經出貨的競品（不是 repo，但影響定位）
