# 讓 agent 自己總結分類

**狀態：規格草稿，還沒實作。** 照這個 repo 的規矩，先把「兩個人可能讀出不同意思」的地方
釘死，變成測試，測試先紅，然後才寫實作。

---

## 為什麼要有

使用者 2026-09-21 回報：

> rename 或 file 的清單應該還要根據 agent 自己讀到的所有檔案去做總結說可以歸類成哪些。
> 而不是因為 rule 裡面只有要歸類 course 就其他都不幫忙分類？

實機資料證實了這件事 —— 不過**證實的方式跟第一眼看到的不一樣**（詳見下面的「前提修正」）。

畫面上寫「could not tell what this is」的檔，`kind` 是有值的，少數幾個 `topic` 也很好用：

```
kind=Other 36 · Homework 13 · Exam 11 · Report 4 · Lecture 2 · Notes 2

topic: "Enabling Edge AI Offloading for XR Devices in Cost-Effective Private 5G Networks"
       "User-guided Seam Carving Image Removal System"
```

而規則層把整個檔丟掉，連 `kind` 都不看：

```js
// core/filing.ts
const course = cleanCourse(opinion.course)
if (!course) continue          // 課名說不出來 → 整個檔放棄
```

`rename` 那邊是第二道閘：prompt 規定「說不出課名就把 confidence 設成 low」，
而 `confidentEnough()` 只收 high／medium。

**結果**：一個檔明明被讀懂了（知道是 Report、知道標題），卻因為「不屬於任何一堂課」
而完全不被幫忙。使用者的 Downloads 裡大半是表單、公文、論文、CV、規格書 —— 也就是說
**這個工具對它實際看到的大部分檔案都束手無策**，而且原因不是看不懂。

---

## 這一期要做的是哪一件事

**不是**把 `Courses/<課名>/<類型>` 換成另一組寫死的資料夾。那只是把一個猜測換成另一個猜測。

**是**：讀完之後回頭看**自己實際讀到了什麼**，提議一套從這些檔案長出來的分法，
然後**讓使用者改、讓使用者核准**。

```
你這 1164 個檔，我讀得懂的有 716 個。看起來可以這樣分：

  課程教材        47 個   CS3103 Computer Networks、作業系統、機器人學⋯⋯
  研究論文        23 個   多半是 arXiv 下載的 PDF
  申請與表單      18 個   推薦書、獎學金、在學證明、eForm
  個人文件         9 個   CV、自傳、讀書計畫
  截圖           126 個   多半沒有文字，靠長相分組

  剩下 493 個我看不出共通點，維持不動。

改哪一組的名字都可以。按「套用」才會動檔案，而且七天內都復原得回來。
```

---

## 預想的預期行為（實作前就定死）

### 0 ・ 哪些檔進得了這一道（殘料，不是全部）

0a. **只看規則放不進去的那一堆。** 一個檔要同時滿足才進來：
   - 已經有看法（`model_views` 有列、過得了新鮮度），而且
   - **`file` 那條路收不了它** —— `cleanCourse(course)` 是空的（課名說不出來），
     或者 `kind` 是 `Other`（分類等於沒分）。

0b. **已經分得好的檔不碰。** 課名說得出來、`kind` 又是 Lecture／Homework／Exam 這種
   有意義的值 → 它本來就有去處（`Courses/<課名>/<kind>`），再讓模型重分一次
   只會讓同一個檔有兩個互相矛盾的目的地（不變量 22）。

0c. **什麼時候跑**：`cleanup scan` 或 `think` 跑完之後，殘料數量 ≥ `MIN_RESIDUE`（初值 20）
   才產生提議。低於這個數就不提 —— 三個檔分成兩組是雜訊，不是幫忙。
   跟寵物的連拍詢問同一個原則：**只在有話說的時候說話**。

### 0d ・ 前提修正：殘料身上沒有東西可以分組（2026-09-21 實測）

原本這份規格寫著「模型早就分類好了，是規則層把它丟掉的」。**實測之後只對了一部分。**

實機 88 筆答案裡，殘料 84 筆，**其中只有 8 筆有 `topic`**。原因是逐檔的 prompt 把
`course` 與 `topic` 綁在同一個問題上 —— 答不出課名的時候整組欄位一起空掉：

```
Peng-Ju_Wen_CV_1.docx
  course = "Unknown"   topic = "Unknown"   kind = Other   confidence = high
  evidence = "AI-RAN LLM Platform 2026"
```

**內容是讀到的**（evidence 是真的引文），只是被問錯問題，所以答案是空的。
那麼 `檔名 | kind | topic` 這種摘要行，對 76/84 的檔等於送
`某檔.docx | Other | Unknown` —— **分組的那一次拿不到任何信號**。

所以這一期多一步：**殘料要先被重新問一次，用一個開放的問題**。

0e. **`describe` pass**：只對殘料跑，問的是
   「這是什麼文件？用你自己的話講，不要硬塞進任何分類」，回 `whatItIs` 與 `subject`。
   - **不動 `PROMPT_VERSION`，不碰現有快取。** 這是**另一個問題**，走自己的快取命名空間
     （`describeKey = sha256(內容) + ':' + DESCRIBE_VERSION`），所以已經問到課名的那些
     一個字都不用重問，之後新的課程教材也照樣走原本那條路。
   - 這是本期唯一新增的逐檔模型呼叫，而且**只跑殘料**、照樣有快取、照樣過機密防線。

0f. 分組那一次拿到的摘要行因此變成
   `檔名 | kind | whatItIs | subject` —— 全部是模型自己產生的短字串，不是檔案原文。

### 1 ・ 範圍與資料來源

1. **只看已經有看法的檔**（`model_views` 有列、而且過得了新鮮度）。沒讀過的不猜、不排隊。
2. **只看清理範圍底下的檔**（`cleanup.roots`），跟其他所有功能同一個範圍。
3. 分組那一次送的是**摘要，不是內容**：一個檔一行 `檔名 | kind | whatItIs | subject`。
   **絕對不送 evidence、不送 file_texts 的原文。** evidence 是從使用者檔案裡引出來的原文，
   逐檔那條路送過一次是必要的（不看內容就答不出來）；分組只需要「模型怎麼描述它」，
   不需要原文，而且量大 40 倍 —— 沒有理由把整批原文再送一次。
4. 檔名是不可信的輸入，一律 `safeName` 之後才進 prompt。

### 2 ・ 分批與合併

5. 1164 個檔塞不進一次 prompt。**一批最多 `GROUP_BATCH` 行**（初值 120），
   分批問，每一批各自回一組分類。
6. 分完之後**再問一次做合併**：把各批的分類名稱去重、合併同義的
   （「Research Papers」與「論文」是同一組）。合併那一次只送**分類名稱與數量**，
   一行檔案摘要都不送。
7. 模型連續失敗就停，跟 `think` 同一條規矩（`MAX_FAILURES_IN_A_ROW`）。
   **半途停掉不留半份提議**：整份提議是一次交易寫進去的。

### 3 ・ 提議的形狀

8. 一組提議包含：`name`（資料夾名）、`why`（一句人話）、`itemIds`（哪些檔）。
9. **`name` 會變成磁碟上的資料夾名**，所以走 `cleanCourse` 同一套清洗
   （去路徑分隔符號、控制字元、Windows 保留名、截長度）。洗完是空的就整組丟掉。
10. **一個檔最多只能出現在一組裡。** 模型把同一個檔放進兩組時，留第一組、其餘忽略，
    不可以讓一個檔被兩條路各搬一次。
11. **沒被分到的檔就是沒被分到**，畫面要講出來有幾個，不可以安靜消失
    （跟「需要你查看」同一個道理）。
12. 組數上限 `MAX_GROUPS`（初值 12）。超過就取檔案數最多的前 12 組，
    其餘併回「沒分到」。太多組等於沒分類。

### 4 ・ 安全性（跟這個專案其他部分同一條線）

13. **提議不是動作。** 這一整支指令**一個檔都不動**，只寫一張提議表。
14. 套用走**既有的歸檔執行層**（`filing.ts` 的搬移與 journal），不新開一條搬檔的路。
    也就是說：先寫 journal、再動檔案、七天內可復原、跨磁碟不支援 —— 全部照舊。
15. **模型碰不到路徑。** 它回的是分類名稱，路徑由程式組、`safeName` 過、再檢查一次
    是不是在 `filed` 底下。跟 P3／P4 同一條不變量。
16. 提議存進資料庫，**下一次重新總結會整份取代**，不會累積出兩份互相矛盾的提議。

### 5 ・ 畫面與指令

17. `node cli.mjs group` —— 產生提議並印出來（**不動檔案**）。
18. `node cli.mjs group --apply [組名…]` —— 套用指定的組；不給就是全部。
19. 面板多一區「提議的分法」，跟改名／歸檔同一種列：勾選框、理由、View contents、
    **一組一顆按鈕**，旁邊永遠有「復原」。
20. 空的時候整區不顯示（跟其他區一樣）。

### 6 ・ 跟現有 `file` 的關係

21. **兩條路並存，不互相取代。** `Courses/<課名>/<類型>` 對真的是課程教材的檔仍然是
    最好的答案（使用者已經在上面累積了 learned 偏好）。
22. **同一個檔不可以同時出現在兩邊的建議裡。** `file` 已經提議的（課名說得出來的），
    `group` 就不提議 —— 否則使用者會看到兩個互相矛盾的目的地。

---

## 已經決定的事（2026-09-21 使用者回覆）

- **`kind` 這個固定 enum 留著。** 它是 `Courses/<課名>/<kind>` 的第二層，
  對真的是課程教材的檔仍然有用，動它會影響已經歸好檔的東西。
- **`PROMPT_VERSION` 不換。** 這一期只加彙總，逐檔的 prompt 一個字都不動，
  所以快取全部留著 —— 使用者不必重跑那 716 個檔。
  「不用作廢快取」本身就是這個設計該守的性質。
- **這一道 pass 只看「規則放不進去的那一堆」**，不是看全部。使用者的原話：

  > 當歸類到 other 時，agent 可能要在掃描完成後看看是不是可以統一做分類之類的

  已經分得好好的檔（課名說得出來、`kind` 是 Lecture／Homework／Exam⋯⋯）
  本來就有去處，再讓模型重分一次只會製造兩個互相矛盾的目的地。
  **剩下來的那一堆才是問題**，而那一堆正是現在完全沒人管的。

## 這一期新增的模型呼叫，成本講清楚

| pass | 對象 | 換快取嗎 | 你的資料上大概是 |
|---|---|---|---|
| 現有的逐檔 view | 全部可問的檔 | 不動 | 716 個（已經在跑） |
| 新增的 `describe` | **只有殘料** | 自己的命名空間，不碰現有快取 | 殘料佔 84/88 → 估 ~650 個 |
| 新增的 `group` 彙總 | 摘要行，分批 | — | ~6 批＋1 次合併 |

`describe` 那一趟是本期最花時間的部分。但它**不作廢任何東西** ——
已經答出課名的那 4 個（以及之後所有真的是課程教材的檔）完全不受影響。

## 測試要先紅的那幾條

1. 沒有任何看法 → 提議是空的，不呼叫模型，不寫表
2. 送出去的 payload **不含 evidence、不含 file_texts 的原文**（逐字比對）
3. 一個檔出現在模型回的兩組裡 → 只進第一組
4. 分類名稱是 `../../etc` → 洗成 `etc`，組不到 filed 以外的地方
5. 分類名稱洗完是空的 → 整組丟掉
6. 組數超過 12 → 取前 12 大，其餘算「沒分到」，而且數字加起來等於總數
7. 模型連續失敗 → 停，而且**不留半份提議**
8. `group` 執行完，磁碟上**一個檔都沒動**
9. 已經被 `file` 提議的檔不會同時出現在 `group` 的提議裡
10. 重新總結一次 → 舊提議整份被取代，不是疊上去
11. `describe` 走自己的快取命名空間 → 跑完之後**現有的 `model_views` 一列都沒變**
12. 已經答出課名的檔**不進 `describe`**（不重問、不花那一次呼叫）
